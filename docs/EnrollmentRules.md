# 排課與整期報名規則

## 學期開放

1. 在草稿學期建立課程與完整場次。
2. 在「學期管理 → 編輯」核對各啟用課程的堂數及完整課表，勾選排課完成，將狀態改成開放報名。
3. 系統檢查每門啟用課程均有有效堂數、場次位於學期期間，並記錄確認管理員與時間。
4. 課程／場次變動會更新學期資料版本，舊的學期確認表單不能直接送出。
5. 開放後鎖定直接增刪場次及修改課程。若整個學期從未有任何報名紀錄，可先停止報名，再退回草稿重排；重新開放須再次確認。

既有已開放學期的排課確認欄位會維持空值，必須由管理員實際核對後確認，系統不代為追認。

## 報名確認

目前仍由後台管理員代辦：選學生及課程 → 核對完整課表與金額 → 與學生確認不提供自行退課退款 → 建立申請。確認頁有效 30 分鐘；改換學生、修改課表或價格後須重新核對。

收款與核准各自需要再次確認。系統保存首次政策確認管理員、時間、政策文字，收款與審核另有原本的操作人與時間。

已核准報名不能使用退回申請的端點辦理退課退款。未獲核准申請的已收款退回功能仍保留，兩者用途不同。未核准申請若報價堂數與現有課表不同，系統阻止收款與核准，保留原紀錄供人工核對。

## 場次刪除

「場次管理 → 刪除」會先展示課程、老師、地點與時間，確認後才送出刪除。只允許草稿學期且該課程沒有任何申請或正式報名紀錄的場次。關聯到其他申請的場次及版本已過期的操作也會被阻止。

已有報名的取消／調課不是直接刪除；本次僅加入刪除限制，尚未建立取消／調課專用流程。

## 部署與驗證

2026/10/11 起，正式報名核准也會檢查每堂 Active Participant（含已核准補課）是否尚有空位；不能只按固定期課正式報名人數推定名額。詳見 [請假與補課規則](LeaveMakeupRules.md)。

- 新 migration：`20261006144721_ScheduleConfirmationAndEnrollmentConsent`，只新增 5 個可空欄位，不修改既有報價、付款、場次或狀態。
- 更新資料庫後重新建置啟動網站。
- 整合檢查：`dotnet run --project Tests/WorkflowChecks --configuration Rules`。程式使用獨立隨機名稱測試資料庫並於完成後移除。
