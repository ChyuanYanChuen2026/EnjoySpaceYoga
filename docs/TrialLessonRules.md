# 體驗生、方案與付款（原訂 9/29）

本輪完成管理員 MVC 的體驗生資料、方案設定、購買確認、待收款訂單、確認收款與堂券啟用。方案價格、堂數與有效天數由管理員自行設定，未預設正式售價。

## 操作與驗收

若網站仍是更新前啟動的版本，先在原本執行網站的終端機按 Ctrl+C，再於 EnjoySpace.Web 目錄執行 `dotnet run --launch-profile http`，使用管理員帳號登入。

1. 開啟 `/Admin/TrialGuests`，新增體驗生，填姓名與電話。來源選「學生介紹」時，必須選介紹學生。
2. 開啟 `/Admin/LessonPlans`，新增體驗方案，設定代碼、名稱、堂數、價格及有效天數，保持啟用。正式學生使用「堂券方案」類型。
3. 開啟 `/Admin/LessonPasses`，新增購買，選購買對象、方案及生效日。生效日不得早於台灣今天。
4. 核對確認頁的對象、價格、堂數與效期，勾選確認後建立訂單。預期付款與堂券均顯示待付款，尚未啟用。
5. 在詳細頁填實收金額、付款方式、實際付款時間，勾選核對後確認收款。預期付款已確認、堂券已啟用。
6. 開啟 `/Admin/Payments`，確認同時可看到原有期課付款與新方案付款，並能返回各自詳細頁。
7. 另建一筆待付款訂單，填取消原因並取消。預期應收款與堂券都取消，不能再收款。

驗收時可使用明確標示「測試」的姓名與方案代碼。已付款紀錄不能用「取消待付款訂單」撤銷；不要為清除測試而刪除付款歷史。

## 已實作規則

- 體驗方案供啟用中的體驗生購買；堂券方案供啟用中的正式學生購買。體驗生轉正式學生的流程尚未包含在本輪。
- 方案可停用，既有購買保留當時名稱、價格、堂數與效期；後續改價不會改寫已建立的訂單。
- 有效天數包含生效日，例如 10/12 生效、30 天有效，最後有效日為 11/10；也可設定不限期。
- 購買確認有效 30 分鐘，綁定管理員、對象與方案版本。重送同一份確認只返回原訂單，不重複建立款項。
- 付款需等於訂單原金額，付款方式可選現金、轉帳或 Line Pay；這是管理員人工記錄，沒有串接支付平台。
- 付款時間使用台灣時間，需在訂單建立至目前之間（容許一分鐘誤差）。已過期的待付款訂單不能啟用。
- 收款與堂券啟用在同一筆交易中完成。取消尚未收款訂單也會一併取消應收款。
- 編輯、收款及取消檢查資料版本；過期表單必須重新載入核對。所有寫入限有效管理員，MVC 表單有防偽檢查。
- 列表每頁 20 筆。價格最多兩位小數，堂數及有限效期天數必須大於零。

## 範圍與驗證

本輪不包含實際體驗排課、堂券預約／取消／扣堂、已收款堂券退款、學生剩餘額度頁，也不代表 Portal 前台已整合完成。

2026/10/12 已通過 136 項服務／資料庫檢查及 17 項 MVC HTTP 檢查，共 153 項，涵蓋既有報名、點名、請假與補課回歸。HTTP 測試使用獨立資料庫，實際登入並送出表單；人工畫面與業務驗收仍待使用者操作。

本機 EnjoySpaceDb 已套用 `20261011131928_AddTrialPlansAndPurchases`。本輪以 EF 產生的指定 migration 區間 SQL 更新，只新增 LessonPlans、LessonPasses 及 TrialGuests.RowVersion；PortalTrialRequest 的模型仍屬另一項未附 migration 的工作，未一併更新，也未宣稱全專案 EF 模型已一致。
