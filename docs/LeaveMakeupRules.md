# 請假與補課：管理員操作與規則

## 已確認的規則

2026/10/11 使用者確認：上課前可請假／取消請假，補課限同一期。跨期及 $100 場地費仍依原定後續階段處理。

- 只接受有效固定期課名單且尚未點名的請假；必填 500 字內原因。
- 請假將原 Participant 改為 OnLeave，釋出該堂名額，保留原名單與出缺席紀錄，建立一筆補課資格。
- 補課資格狀態：Available（可使用）→ Reserved（申請待審）→ Consumed（已核准使用）。取消原請假後為 Revoked（已撤銷）。
- 一筆資格同時最多一個待審或已核准申請。待審鎖住資格但不占座位；核准時才占位，因此送出時有空位不保證核准時仍有空位。
- 目標場次須同一期、尚未開始，課程啟用且接受補課，學期完成排課確認且狀態為 Open 或 Closed。原本已在名單上的固定課堂不能拿來補課。
- 核准建立 Makeup Participant 與未點名 AttendanceRecord，並保存審核人、時間與備註。目標課堂可使用現有出缺席功能。
- 退回申請須填原因並釋回資格。取消申請也須填原因；已核准補課限開始前、未點名時取消，取消會釋出名額。
- 補課不能再次請假產生第二筆資格；未開始且未點名時可取消後重新申請。
- 原請假要取消，須先取消待審／已核准補課，並確認原課堂尚未開始且仍有空位。若原課堂已滿，取消失敗，資格及請假狀態保持原樣。
- 所有操作均檢查管理員角色、防偽 token 與資料版本。資格、名單及狀態變更在同一交易完成。
- 名額統一按 Active Participant 計算，含固定期課與補課；正式報名核准、補課核准、取消請假都會重新檢查逐堂名額。

## 操作驗收

1. 重新啟動網站並以管理員登入。從「場次管理 → 名單／點名」找一堂尚未開始、已有正式入班學員的課。
2. 在固定期課學員下按「登記請假」，填原因後確認。原名單應顯示「請假中」，有效人數減一。
3. 開啟左側「請假與補課」。在「請假紀錄」或「補課資格」選「申請補課／選擇補課場次」。
4. 選擇同一期另一堂有空位的課，送出後查看「補課申請／審核」：申請為待審，資格為申請待審中。
5. 按「核准並加入名單」，再開啟「目標課堂名單」：學員應顯示「補課」，狀態為未點名。
6. 回申請頁填取消原因，按「取消補課並釋回資格」：目標名單保留紀錄，但標為非有效名單。
7. 回「請假紀錄」，在原課堂尚未開始且仍有空位時按「取消請假並撤銷資格」：原名單恢復，補課資格已撤銷。

找不到可選補課場次時，先確認同一期有另一門啟用、接受補課、完成排課確認且尚未開始的課，以及剩餘名額。只剩學生原本就報名的課堂時不會列出。

## 資料與部署

Migration：`20261011123639_AddLeaveAndMakeupWorkflow`，新增 LeaveRequests、MakeupEntitlements、MakeupRequests；ClassSessionParticipants 新增可空的 MakeupRequestId。

補課 Participant 的 CourseEnrollmentId 保留來源固定期課報名，用來追溯資格；ClassSessionId 指向目標補課場次，ParticipationType 為 Makeup。原本的期課唯一索引改為只約束 Regular，允許取消後重新申請同一補課場次，同時維持 Active Student 唯一索引。

更新使用 `dotnet ef database update`。不要在已有請假／補課紀錄的環境直接回復此 migration，因為回復會刪除這些新增資料。

## 驗證方式

- `dotnet run --project Tests/WorkflowChecks --configuration Rules`：102 項服務／SQL 整合檢查。
- `dotnet run --project Tests/WorkflowChecks --configuration Rules -- --http`：再加入 10 項實際 MVC HTTP 檢查，共 112 項。
- 使用隨機名稱的獨立 SQL Server 資料庫。HTTP 模式使用該資料庫與臨時測試管理員登入，測完停止自建網站並移除資料庫，不變更開發資料庫帳號。
- 測試含資料庫升級、資格不可重複使用、同時搶最後一個名額、補課占位阻止固定班超額、取消請假滿額檢查，以及取消與退回的資格釋回。
