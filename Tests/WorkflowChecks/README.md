# 報名與排課流程整合檢查

執行 `dotnet run --project Tests/WorkflowChecks --configuration Rules`。

使用本機 SQL Server 的 Windows 驗證，建立隨機名稱的獨立測試資料庫，完成後自動移除。帳號需有建立資料庫權限。可用 `ENJOYSPACE_TEST_SERVER` 指定測試伺服器；程式不接受既有資料庫名稱，也不讀取應用程式的開發資料庫連線設定。

檢查包含學期完整排課與確認、停止報名後的受控草稿還原、場次刪除及版本衝突、確認頁資料防竄改、重複報名、三階段確認、已核准報名禁止退回、舊報價堂數衝突，以及資料庫端篩選／排序／分頁。

逐堂名單與出缺席檢查：核准後每堂建立一筆名單與未點名紀錄、既有正式報名升級補建、排除未核准申請、管理員權限、未開課限制、跨場次送出、狀態與備註驗證、更正原因、過期版本拒絕、出席／遲到／缺席／重設未點名，以及停用名單限制。

請假／補課檢查包含來源資格、上課前截止、同一期限制、資格保留與釋回、取消往返、過期表單、兩位學生同時競爭最後名額、固定班報名與取消請假不可超額。

體驗生／方案檢查包含權限、介紹學生、資料版本、價格與堂數驗證、效期、確認 token、防重複購買、購買快照、收款金額／時間、付款啟用原子性及未付款取消。預設共 136 項檢查。

加入 `-- --http` 可執行實際 MVC 登入、防偽 token、表單驗證、請假到補課再取消，以及體驗生新增、方案建立、重複購買確認、收款啟用和付款列表，共 153 項。會啟動使用獨立測試資料庫的本機網站，測完自行停止，不使用開發資料庫帳號。

Migration 檢查會在隨機測試資料庫內先回復空的請假／補課 migration，移除新增的名單／出缺席兩表，再執行兩次 migration 的 Up operations，模擬已有正式報名資料的升級；不是整段歷史 migration 的重播，也不會存取開發資料庫。

方案 migration 另建 `EnjoySpace_TrialMigration_` 隨機資料庫，限制模型為該 migration 所含實體，執行 Down／Up 後確認既有體驗生保留及 rowversion 正常。完成後移除；主測試與 HTTP 測試仍使用目前完整模型。此隔離避免其他未完成模型的外鍵影響歷史 migration 測試，不代表其他模型已有可套用 migration。
